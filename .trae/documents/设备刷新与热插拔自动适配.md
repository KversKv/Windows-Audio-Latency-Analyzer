# 设备刷新与热插拔自动适配

## Context

“刷新设备”按钮的 UI → Worker → DeviceService → AudioDeviceManager 调用链完整，但真实后端只重复 `sd.query_devices()`，未更新 WASAPI 原生设备表，因此可能一直返回旧列表。当前也没有自动监测；设备仅以 PortAudio 索引恢复选择，插拔导致索引重排时可能误选其他设备。

已确认当前 sounddevice/PortAudio 提供 `PaWasapi_UpdateDeviceList`。真实冒烟进一步确认随 sounddevice 分发的 PortAudio V19.7.0 默认将 `PA_WASAPI_MAX_CONST_DEVICE_COUNT` 编译为 `0`，该接口固定返回 `paInternalError (-9986)`。因此优先使用专用接口，并对该返回值增加仅限空闲扫描的 PortAudio 重新初始化回退；不引入 COM、WMI、QtMultimedia 或新依赖。

## 目标行为

- 手动刷新先更新 WASAPI 设备表，再读取同一批新设备；无论列表是否变化都有明确成功或失败反馈。
- 空闲时低频自动扫描，新增、移除及能力变化自动反映到界面；无变化时不重建下拉框、不发跨页信号、不刷状态栏。
- 新设备插入不抢占仍有效的当前选择。
- 运行期间依据“上次有效设备快照 + 当前 PortAudio ID”保持选择：同设备改索引且描述唯一时跟随；同名同规格导致歧义时不猜测。
- 选中设备消失时显示“原设备不可用或无法唯一识别，请重新选择”的空态，禁止开始测量但允许用户另选；不静默切到第 0 项，旧偏好不被 `None` 覆盖，唯一重插时可恢复。
- 测量期间停止自动扫描，不改设备、不重建流；会话线程收尾后补扫。设备断开仍走现有错误与资源释放路径，不自动续测。

## 实施步骤

### 1. 修复真实设备枚举

修改 [audio_backend.py](file:///d:/CodeProject/TRAE_Projects/Windows%20Audio%20Latency%20Analyzer/audio/audio_backend.py#L234-L257) 的 `SoundDeviceBackend.list_devices()`：

- 在 Windows 且 Host API 中存在 WASAPI 时，先经 `sd._lib.PaWasapi_UpdateDeviceList()` 更新设备表，再调用 `sd.query_devices()`。
- 原生接口返回 `-9986` 时，在 UI 已保证无活动会话、无活动流且扫描单飞的前提下，通过 `sd._terminate()` / `sd._initialize()` 重建设备表；若上次初始化已失败，则先恢复初始化并直接使用此次新快照。开始测量入口同时拒绝扫描未结束的请求。
- 其他原生错误继续经 `sd._check()` 检查；沿用现有 WASAPI 过滤、一致快照映射和 `AudioBackendError` 转换，失败时不得继续返回旧设备表。
- 非 Windows 不调用 WASAPI 扩展；活动会话中禁止任何 PortAudio 重启或设备表刷新。

### 2. 增加有界自动刷新调度

修改 [test_page.py](file:///d:/CodeProject/TRAE_Projects/Windows%20Audio%20Latency%20Analyzer/ui/test_page.py#L548-L697)：

- 保留 `refresh_devices()` 作为手动入口，新增私有统一请求入口和自动槽，避免 `QPushButton.clicked(bool)` 参数歧义。
- 复用现有 `DeviceEnumerationWorker` 与 QThread，所有原生设备访问仍在后台线程；扫描单飞，不排队制造并发 Worker。
- 使用单发 `QTimer`：初始手动扫描收尾后开始自动调度；正常间隔 2 秒，连续失败按 2/4/8/16/30 秒退避并封顶，成功后恢复 2 秒。手动点击可立即扫描。
- 自动扫描不显示短暂的“正在读取”状态；无变化自动结果保持静默。手动结果及错误恢复仍使用现有 `devices_refreshed` / `refresh_failed` 通知主窗口。
- 测量成功启动后停止定时器，`controller.finished` 后自动补扫；`shutdown()` 首先停止定时器，迟到结果受关闭保护，保留现有 2 秒有界线程等待。

### 3. 安全保持设备选择

修改 [test_page.py](file:///d:/CodeProject/TRAE_Projects/Windows%20Audio%20Latency%20Analyzer/ui/test_page.py#L607-L697) 与 [main_window.py](file:///d:/CodeProject/TRAE_Projects/Windows%20Audio%20Latency%20Analyzer/ui/main_window.py#L198-L207)：

- 保存输出、输入各自最后有效的 `AudioDevice` 快照和 ID；使用名称、Host API、输入/输出声道能力及模拟标记做运行期间描述匹配，不把可能随系统格式变化的默认采样率作为身份。
- 优先保留“ID 与描述均一致”的设备；ID 失效或描述不符时，仅允许唯一描述匹配跟随新索引，多个匹配则进入明确空态。
- 首次无偏好时仍选择首个可用设备；已有偏好但无法解析时插入 `None` 占位项，不自动回退第 0 项。
- 下拉框是否可编辑由“是否存在有效候选项”决定，开始按钮仍要求当前两侧选择均有效。
- 只有用户或唯一重匹配得到有效设备时才更新偏好；主窗口在某一侧当前选择为 `None` 时保留该侧已保存 ID。
- 比较新旧 `DeviceInventory`，仅变化时重建 ComboBox、重载校准上下文并发出必要信号；仅实际选择变化时发 `device_selection_changed`。

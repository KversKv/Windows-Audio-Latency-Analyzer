# 07 FLOW GUIDE - 业务流程指引

## 会话主流程

```text
IDLE → DEVICE_CHECK → OPENING_AUDIO → WARMUP → READY
     → RUNNING → ANALYZING → (WAIT_NEXT → RUNNING)* → COMPLETED
```

- `DEVICE_CHECK` 在工作线程重新扫描并按设备 ID 验证输入/输出能力；失败进入 `DEVICE_ERROR`。
- 真实模式按播放、采集顺序开流，先启动采集再启动播放；播放流在会话内保持打开。预热期间持续播放背景音并排空采集缓冲。
- 离线模拟不打开实时流，直接生成有已知延迟的合成响应，并明确标注 simulation。
- 每次测量先读取并清理当前采集缓冲，记录采集样本起点；再按播放绝对样本索引调度 Chirp，并按前导、最大延迟、尾部配置收集窗口。
- 互相关和质量判定在 Worker 中运行。每次尝试都追加 `MeasurementRecord`，包括无信号、低 SNR、超范围、超时和时间轴/时钟无效情况；统计仅使用有效记录。

## 有效性与计时

- 相关峰判定回答“采集波形中是否找到符合质量阈值的刺激响应”；它本身不证明播放与采集样本的绝对时间可比。
- 只有 DAC/ADC 时间锚点可用、采集时间轴连续，且两条流有已验证的共同时间原点时，才计算并纳入绝对延迟统计。Windows WASAPI + PortAudio 19.7.0 可由后端声明共同 QPC 时基；其他 host API/build 需先建立映射。
- 共同时间基准缺失/不匹配时，保留捕获波形、互相关信息和无效原因，raw/compensated latency 均为 `None`。禁止根据同一后端实例推定零偏移。
- 有效值仍须记录校准配置和时间限制。声学模式测量完整播放—耳机—空气—麦克风链路，不单独表示耳机换能器延迟。

## 停止、错误与保存

- 用户停止通过 `threading.Event` 通知 Worker；当前阻塞轮询最多等待一个轮询间隔，随后停止调度、关闭流并输出已有完整记录。
- 欠载、溢出、丢帧、设备断开、流意外停止或超时使会话进入对应错误终态。错误终态中的已有记录可保存；无记录的失败不能保存。
- 持久化 pending 期间冻结当前快照与 `session_id`；成功后状态机转为 `SAVED`，快照仍保留原业务终态，便于追溯。
- `QThread.wait()` 超时只代表调用方停止等待，不会强制中断 PortAudio 原生调用。窗口关闭应取消并允许稍后重试；要强制限制原生调用时长需将相关原生工作隔离到可终止的辅助进程。

## 测量方法验收

- 合成信号用于验证算法的已知延迟、噪声、幅度、极性和边界处理，不代表真实设备精度。
- 真实设备验收需用独立已知延迟参考验证时基映射、偏移和漂移；记录设备、采样率、缓冲、信号路径、麦克风位置、电平和环境。
- 每个设备/路由组合需重复采集并报告有效率与分布（中位数、P90/P95、标准差）；未验证的精度容差不得写成产品保证。
